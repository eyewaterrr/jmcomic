# 后续开发计划（候选）

整理于 2026-10-24，依据是第一版的运行情况；v1.1 完成的项目已在表里标出。下面按优先级排列，具体做哪些由所有者决定，定下来的项目会移到 [progress.md](progress.md)。

## 现状

**已完成：** 入库、按页阅读、收藏 PDF、白名单、每日备份都已上线，两本作品的完整流程实测通过（数据见 [operations.md](operations.md)）。

**还没完成：** 手机验收，以及在 BotFather 里启用 Main Mini App。

**主要约束：**

- **CPU：** 只有 1 核，下载解码约 0.5 秒/页。
- **磁盘：** 剩余约 3.8GB，页面缓存上限 1GB。
- **存储：** 书库和收藏都在 Telegram 上。

## 不建议做

- **把页面发成 Telegram 原生相册：** 图片会被压缩到 2560px，一本要发几十条消息，还会碰到频道发送频率限制。
- **改回用官方 Bot API 传文件：** 官方 Bot API 上传最多 50MB、下载最多 20MB，大本传不了。
- **在这台服务器上放大缓存或存本地书库：** 磁盘不够。

- **分布式下载**（把下载、拼图交给其他电脑、VPS 或云平台）：2026-10-24 评估后不采用，原因和实测数据见 [environment.md](environment.md) 第 9 节。

## 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| JM 接口或防爬规则变化 | 搜索、下载失败 | 2.2 升级流程；jmcomic 上游一般跟进得很快 |
| Telethon / Telegram 协议变化 | 部分功能报错。已遇到过一次：按钮类型改名 | 固定依赖版本，升级前先跑测试（1.6） |
| 磁盘空间继续减少 | 剩余不到 1.5GB 时，新任务会被拒绝 | 2.3 提醒；查清是哪些服务在占用增长 |
| Telegram 删除频道或封号 | 书库和收藏会一起受影响 | 2.4 加备用管理员；需要时再做 4.4 |
| 单核 CPU | 长篇入库慢（约 0.5 秒/页） | 任务排队、后台串行执行，不影响阅读；需要更快时给本机加 CPU 核心 |

## 建议顺序

1. 第 0 步。
2. 1.1、1.2、1.3：日常使用中体验提升最明显。
3. 2.1、2.2、2.3：长期运行的保底措施。2.4 随时可以做。
4. 第 3 批：看书库规模和使用习惯再定。

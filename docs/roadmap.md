# 后续开发计划（候选）

2026-11-08 按 v3 重新整理。具体做哪些由所有者决定，定下来的项目会移到 [progress.md](progress.md)。v1.1 时期的候选项目里，和入库、书库频道有关的已随 v3 失效，从这里删掉了。

## 现状

**已完成：** v3（阅读从 JM 取、服务器只缓存原图、前端还原、收藏只记收藏夹、上传精选单独操作），单元测试和集成测试通过。

**还没完成：** 手机验收、部署、在 BotFather 里启用 Main Mini App、搜索页两版二选一。

**主要约束：**

- **流量：** 服务器按上下行双向计费。v3 之后，大头是从 JM 取原图和发给手机，各 0.77 份。
- **CPU：** 1 核。阅读时不再解码，只有上传精选时生成 PDF 要用 CPU。
- **磁盘：** 剩余约 5GB，原图缓存上限 2GB。
- **JM：** 阅读完全依赖 JM 在线；想长期保留的作品要上传精选。

## 不建议做

- **把页面发成 Telegram 原生相册：** 图片会被压缩到 2560px，一本要发几十条消息，还会碰到发送频率限制。
- **改回用官方 Bot API 传文件：** 上传最多 50MB，长篇 PDF 传不了。
- **在这台服务器上放大缓存：** 磁盘不够；缓存只是为了省流量和翻页快，不是书库。

## 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| JM 下架作品、接口变化或暂时连不上 | 没缓存、没上传精选的作品看不了 | 想长期保留的上传精选；jmcomic 自动更新照旧 |
| 每次阅读都从 JM 取 | 可能被 JM 限流 | 按需下载加预读窗口，同时最多 4 个下载 |
| 手机内存 | 长篇上下滑动时 Canvas 太多 | 只保留屏幕附近的 Canvas，离远了就释放 |
| Telethon / Telegram 协议变化 | 部分功能报错（遇到过一次按钮类型改名） | 固定依赖版本，升级前先跑测试 |
| Telegram 删除频道或封号 | 精选受影响 | 2.3 加备用管理员；需要时再做 3.5 |
